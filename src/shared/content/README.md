# Shared content contracts

`models.ts` is the serializable boundary shared by Gatsby and Astro. Views receive plain content, blocks, site settings, and media descriptors; they do not receive `Queries.*`, Gatsby nodes, `localFile` trees, React elements, or credentials. Strapi Blocks and dynamic-zone data remains structured JSON until a React view renders it.

`gatsby-adapter.ts` is the Gatsby-side adapter. It selects only fields used by shared views, translates Gatsby's snake-case component fields to stable names, converts Gatsby image data to `MediaDescriptor`, and extracts only the requested `body` or `content` arrays from `internal.content`. Media descriptors preserve source URLs, alt text, intrinsic dimensions, constrained `sizes`, responsive fallback candidates, and format-specific AVIF/WebP source sets. The React `Image` renderer outputs `<picture>` only when alternate formats exist, carries each source's size hint, and accepts fit/loading presentation props. Hero images load eagerly with high priority; other images default to lazy loading and async decoding. Malformed or absent optional content is omitted. A REST adapter should map fields into these same models, keep Blocks/dynamic-zone values as JSON, and keep its server token outside the returned data.

`shared/data/site-data.tsx` defines the serializable site-wide settings used by shared React UI: site metadata, tracking IDs, announcement content, and clinic options. Gatsby provides these through `src/adapters/gatsby/shared-data.tsx`, mounted around one root React tree in `gatsby-browser.tsx` and `gatsby-ssr.tsx`. The SEO Head API runs outside that tree, so its Gatsby wrapper is `src/adapters/gatsby/seo.tsx`. Astro can provide the same values through `SiteDataProvider`; each independently hydrated React island must include its own provider rather than relying on context to cross island boundaries.

`urls.ts` holds pure detail-path rules. Blog, condition, provider, and clinic paths keep trailing slashes. Clinics use the current lowercase, whitespace-to-hyphen name fallback when no explicit slug exists. Service updates retain the `/service-updates/YYYY/MM/slug/` route; missing or invalid dates and missing slugs return `null`. Inspection corrected the earlier undated-fallback assumption: `gatsby/create-pages.js` formats `moment(node.date)`, and Moment treats a missing date as the current build date. There is no undated service-update route in the captured baseline, so published records require a valid date and drafts can wait until one exists.

`validateContentRecord(record, family, mode)` provides the publishing boundary. Draft mode accepts incomplete editorial records. Published mode requires an ID, title, and route for that content family; a clinic name can supply the fallback slug. Optional body, content, and media fields remain optional. Run it on normalized records before emitting public routes.

Adapters preserve the ordering selected by their query. Where REST must recreate it, use `sortByOrder` for order-based condition/provider lists and `sortByDateDescending` for blog/update lists; both helpers preserve source order for ties, and invalid/missing dates sort last. Keep existing display limits and homepage retired-provider filtering at the consuming query/view boundary. Contract fixtures are in [`tests/infrastructure/content-contracts.test.mjs`](../../../tests/infrastructure/content-contracts.test.mjs); the captured route reference remains [`tests/ui/routes.json`](../../../tests/ui/routes.json).
