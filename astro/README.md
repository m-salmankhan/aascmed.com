# Astro stage 1 proof

This isolated candidate uses Astro 6.4.2, `@astrojs/react` 7.1.0, `@astrojs/node` 10.1.4, React 18.3.1, and Emotion 11.14.0 on Node 22.23.4. The standard React integration's `jsxImportSource: '@emotion/react'` works in both builds; no custom renderer, extraction hook, or client-side style workaround is used. Emotion Global and component styles are present in first-paint HTML. The proof page loads the same Poppins stylesheet as Gatsby. Two separate React islands hydrate independently.

`src/components/header/hero-base.tsx` is the Gatsby-free Hero extraction, `src/components/layouts/columns.tsx` is the shared Columns/Column extraction, and `src/styles/global.ts` is the existing Gatsby global style object extracted unchanged from `App`. Gatsby's existing `Hero` wrapper still supplies its Gatsby `Navigation`; `half-columns.tsx` re-exports the same layout components and Gatsby's `App` still renders the extracted global object. The Astro view passes a serializable `MediaDescriptor` to the shared React `HeroImage` renderer; the TSX view creates the `<img>` node without importing Astro components or Gatsby image APIs. The maintained `/assets/hero-bg.png` is emitted through Astro's existing static directory.

## Draft boundary and safety

The `/` SSR route is a **local/candidate proof only**. It renders draft content when `ASTRO_DRAFT_API_URL` and optionally `ASTRO_STRAPI_TOKEN` are configured. It must remain behind the existing preview authentication boundary before any deployment; this proof does not implement authentication. SSR responses are `private, no-store`, upstream requests are `no-store`, bounded to 1.8 seconds, request `status=draft`, and parse Strapi's `{ data: { title } }` response. Missing configuration, timeout, non-2xx response, malformed response, or disallowed URL falls back to an explicitly labeled fixture; that fixture is not evidence of fresh CMS data. The static target always uses the fixture and never reads either secret environment variable.

The endpoint should be a specific Strapi REST resource that returns a title in its flattened data object. Only HTTPS is accepted except HTTP localhost for local proof; redirects are rejected. No draft is cached between requests.

Public Astro settings use `PUBLIC_API_BASE_URL` and `PUBLIC_MAPBOX_API_KEY`; Astro may compile these into browser assets. Preview-only settings are separate: `ASTRO_DRAFT_API_URL` and `ASTRO_STRAPI_TOKEN` are read only by the server module. Do not pass either preview setting to a static-site build. Gatsby continues to use its existing `GATSBY_API_BASE_URL` and `GATSBY_MAPBOX_API_KEY` client settings, with `STRAPI_TOKEN` reserved for its server-side source plugin.

WEB-30's server-only content adapter reads `ASTRO_STRAPI_API_URL` for published static-build reads and `ASTRO_DRAFT_STRAPI_API_URL` for request-time draft reads. Both values are Strapi origins (for example `https://cms.example.test`); the adapter constructs `/api/<content-type>` requests, sends explicit `status=published` or `status=draft`, paginates in batches of 100 up to 1,000 records per type, and uses per-type population maps. `ASTRO_STRAPI_TOKEN` is attached only to draft requests. Keep these variables in the server/build environment; do not prefix them with `PUBLIC_`. `ASTRO_DRAFT_API_URL` remains the single-resource proof endpoint used by the existing homepage proof.

`src/server/content/loaders.ts` exports `getPublishedBuildSnapshot()` for build consumers; it memoizes the six published collections only when `PUBLIC_ASTRO_TARGET` is `static`. Node build hooks that import the module before Vite runs can pass `{ staticBuild: true }` explicitly. The cache belongs to one module instance, so separate Astro build contexts may each fetch their own snapshot. Draft and SSR reads remain uncached. `src/server/content/routes.ts` exports `getPublishedRouteManifest()` for static path/sitemap consumers. It enumerates only published blog, provider, condition, clinic and service-update routes. SSR draft lookup should call an individual loader with the explicit `draft` mode and a slug/document ID filter; it must not enumerate draft URLs.

## Styling decision

Keep Emotion for the early migration: Astro's standard React integration emits usable SSR styles and the interaction remains deterministic. Emotion's default SSR style tags make `:nth-child(2)` unsafe when targeting siblings; `Column` uses a semantic class plus `:nth-of-type(2)` so inserted `<style>` siblings do not shift the grid column's type position. A broad conversion is not warranted by this proof. The Astro package aliases React, ReactDOM, and Emotion to its own single local package copies for shared-source imports, preventing a second runtime from entering the candidate build. Gatsby source remains on its established dependencies and is not routed through Astro's runtime. The proof's fixed `stylesGlobal` object is emitted by Astro; checks confirm all tested global rules are present in the initial HTML.

## Run and verify

From this directory, use `corepack yarn install`, `corepack yarn typecheck`, `corepack yarn build:static`, `corepack yarn build:ssr`, and `corepack yarn verify:proof` (the last command starts a local mock Strapi response and compiled SSR server). Start the compiled candidate with `corepack yarn start:ssr`. After installing the root package's Playwright dependency and Chromium, run `node astro/scripts/verify-browser.mjs` from the repository root while the SSR server is listening on `127.0.0.1:4321`. The counter and draft badge are separate `client:load` islands.

The local mock verification observed `status=draft`, rendered three successive titles (A/B/C), returned to the fixture after a 1.8-second upstream timeout, a 503 response with an open body, and malformed data, and confirmed `private, no-store`. The open error body was cancelled promptly. Every successful SSR response contained representative Emotion Global and column rules, and style markup remained exactly 5,232 characters across the three requests. The static output includes the fixture, representative extracted global rules and component style tags, the second-column `nth-of-type(2)` rule, and the maintained hero image; it contains no configured test token. Playwright verified SSR content and computed styles with JavaScript disabled: a Poppins font face loaded, and the second column's top margin is 32px on mobile and 0px on desktop. With JavaScript enabled, the counter incremented and the separate draft badge hid without changing the counter; no console errors, page errors, or hydration warnings were captured. Static first-paint styling was verified from generated HTML rather than in a separate static browser session.
