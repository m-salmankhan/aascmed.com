# Astro stage 1 proof

This isolated candidate uses Astro 6.4.2, `@astrojs/react` 7.1.0, `@astrojs/node` 10.1.4, React 18.3.1, and Emotion 11.14.0 on Node 22.23.4. The standard React integration's `jsxImportSource: '@emotion/react'` works in both builds; no custom renderer, extraction hook, or client-side style workaround is used. Emotion Global and component styles are present in first-paint HTML. The proof page loads the same Poppins stylesheet as Gatsby. Two separate React islands hydrate independently.

`src/components/header/hero-base.tsx` is the Gatsby-free Hero extraction, `src/components/layouts/columns.tsx` is the shared Columns/Column extraction, and `src/styles/global.ts` is the existing Gatsby global style object extracted unchanged from `App`. Gatsby's existing `Hero` wrapper still supplies its Gatsby `Navigation`; `half-columns.tsx` re-exports the same layout components and Gatsby's `App` still renders the extracted global object. The Astro view passes serializable media descriptors and creates the `<img>` node inside React. The maintained `/assets/hero-bg.png` is emitted through Astro's existing static directory.

## Draft boundary and safety

The `/` SSR route is a **local/candidate proof only**. It renders draft content when `ASTRO_DRAFT_API_URL` and optionally `ASTRO_STRAPI_TOKEN` are configured. `ASTRO_DRAFT_API_URL` must be the complete Strapi REST resource URL (for example, a collection or entry resource), not a separate draft CMS host or base URL. The proof adds `status=draft` to select preview content. It must remain behind the existing preview authentication boundary before any deployment; this proof does not implement authentication. SSR responses are `private, no-store`, upstream requests are `no-store`, bounded to 1.8 seconds, and parse Strapi's `{ data: { title } }` response. Missing configuration, timeout, non-2xx response, malformed response, or disallowed URL falls back to an explicitly labeled fixture; that fixture is not evidence of fresh CMS data. The static target always uses the fixture and never reads either secret environment variable.

The endpoint must be a specific Strapi REST resource that returns a title in its flattened data object. Only HTTPS is accepted except HTTP localhost for local proof; redirects are rejected. No draft is cached between requests. This setting exists only for the Stage 1 proof. A later production loader should use a server-only Strapi base URL, address the resource it needs, and request `status=published`; no production CMS loader is implemented here.

Public Astro settings use `PUBLIC_CONTACT_API_BASE_URL` and `PUBLIC_MAPBOX_API_KEY`; Astro may compile these into browser assets. The contact API base URL is for contact-form submissions and is separate from the Strapi CMS URL. Gatsby continues to use its existing `GATSBY_API_BASE_URL` and `GATSBY_MAPBOX_API_KEY` client settings for compatibility; `GATSBY_API_BASE_URL` also names the contact-form backend, not Strapi. `STRAPI_TOKEN` remains reserved for Gatsby's server-side source plugin. The Stage 1 proof's `ASTRO_DRAFT_API_URL` resource and `ASTRO_STRAPI_TOKEN` are read only by the server module. Do not pass either preview setting to a static-site build.

## Styling decision

Keep Emotion for the early migration: Astro's standard React integration emits usable SSR styles and the interaction remains deterministic. Emotion's default SSR style tags make `:nth-child(2)` unsafe when targeting siblings; `Column` uses a semantic class plus `:nth-of-type(2)` so inserted `<style>` siblings do not shift the grid column's type position. A broad conversion is not warranted by this proof. The Astro package aliases React, ReactDOM, and Emotion to its own single local package copies for shared-source imports, preventing a second runtime from entering the candidate build. Gatsby source remains on its established dependencies and is not routed through Astro's runtime. The proof's fixed `stylesGlobal` object is emitted by Astro; checks confirm all tested global rules are present in the initial HTML.

## Run and verify

From this directory, use `corepack yarn install`, `corepack yarn typecheck`, `corepack yarn build:static`, `corepack yarn build:ssr`, and `corepack yarn verify:proof` (the last command starts a local mock Strapi response and compiled SSR server). Start the compiled candidate with `corepack yarn start:ssr`. After installing the root package's Playwright dependency and Chromium, run `node astro/scripts/verify-browser.mjs` from the repository root while the SSR server is listening on `127.0.0.1:4321`. The counter and draft badge are separate `client:load` islands.

The local mock verification observed `status=draft`, rendered three successive titles (A/B/C), returned to the fixture after a 1.8-second upstream timeout, a 503 response with an open body, and malformed data, and confirmed `private, no-store`. The open error body was cancelled promptly. Every successful SSR response contained representative Emotion Global and column rules, and style markup remained exactly 5,232 characters across the three requests. The static output includes the fixture, representative extracted global rules and component style tags, the second-column `nth-of-type(2)` rule, and the maintained hero image; it contains no configured test token. Playwright verified SSR content and computed styles with JavaScript disabled: a Poppins font face loaded, and the second column's top margin is 32px on mobile and 0px on desktop. With JavaScript enabled, the counter incremented and the separate draft badge hid without changing the counter; no console errors, page errors, or hydration warnings were captured. Static first-paint styling was verified from generated HTML rather than in a separate static browser session.
